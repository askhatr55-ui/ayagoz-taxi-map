# Аягоз: исправление сервера карты

Подготовлено 10 октября 2026 года. Изменения сохранены локально и проверены тестами. GitHub и работающий Render пока не изменены: авторизованный доступ к управлению этими сервисами отсутствует. Визуальная проверка не выполнена, поскольку инструмент браузера сообщил об отказе в разрешении.

## Причина полностью пустой карты — подтверждена сообщением браузера

MapLibre выдаёт: Failed to construct Request: Failed to parse URL from /tiles/13/5926/2848.pbf. В style.json указаны относительные адреса тайлов, которые не принимаются при создании Request. Версия 3.1.1 выдаёт полные URL. На Render они имеют вид https://ayagoz-taxi-map.onrender.com/tiles/{z}/{x}/{y}.pbf?v=...; локально — http://localhost:3000/tiles/.... Дополнительный тест проверяет создание Request без базового адреса и HTTPS за прокси Render. Для явной фиксации домена можно задать PUBLIC_ORIGIN=https://ayagoz-taxi-map.onrender.com в Environment сервиса.

## Остальные результаты диагностики

Проверен конкретный коммит GitHub `db2d8d55b2fef3acfea13cfe910e545e754709ec` (сообщение Add files via upload). Через Git Trees API подтверждены README.md, package.json, server.js и ayagoz-v3.mbtiles. Старой карты ayagoz.mbtiles, addresses.json, YAML-профиля и extract_addresses.py в этом коммите нет. Страница репозитория показывала устаревший список: выводы основаны на дереве конкретного коммита и содержимом blob, а не на этой странице.

Сервер этого коммита открывает `./ayagoz.mbtiles`, которого в коммите нет. Он также ограничивает выдачу и источник масштабом 14. Это подтверждённая ошибка: такой новый деплой не сможет открыть файл карты; после одной замены имени ограничение всё равно отрежет масштабы 15–16.

Render отвечает другим кодом: /health сообщает ayagoz-v3.mbtiles, 1154 тайла, масштабы 10–16 и 9 слоёв. Там доступны /style.json и расширенный интерфейс, которых нет в GitHub-сервере. Точный коммит работающего деплоя не раскрыт в /health. Вероятность неудачного последнего деплоя высока, но подтвердить её можно только журналами и настройками Render. Нельзя утверждать, что причина именно в выбранной ветке или автообновлении.

Локальный файл совпадает с GitHub MBTiles: его Git blob SHA-1 — `8714b0bba223af831ceddc806aa30b760fdcaf6d`, как в дереве коммита. SHA-256 файла: `4d3ffc8cdceecc4fea2b4848abeb561c63a5f0ee3deaeead7c57eecf80e1a011`. Размер — 2 002 944 байта.

Из 35 HTTP-проверок Render по пяти областям и масштабам 10–16: 31 ответ 200 побайтно совпал с распакованным локальным тайлом; 4 ответа 204 соответствуют отсутствующим локальным тайлам. В этой выборке XYZ→TMS работает правильно. Render отдаёт несжатый PBF без Content-Encoding: это корректно и само по себе не является ошибкой gzip. Полный бинарный файл на Render не скачивался, поэтому совпадение всех его тайлов с локальным файлом не утверждается.

Проверены все 1154 локальных тайла: SQLite integrity_check = ok, каждый gzip распаковывается, каждый protobuf читается диагностическим скриптом. На z10 только places; дороги начинаются с z11, здания с z13, POI с z14, адреса с z15. Эти уровни заложены в файле. Проверенные восточная точка 80.47/47.965 на z14–16 и северная 80.4366/47.99 на z16 не имеют тайлов. Пустота в этих точках не устраняется изменением HTTP-кода. Отсутствие данных в MBTiles ещё не доказывает отсутствие объектов в исходном OSM: при необходимости нужно сравнить с исходным PBF и профилем генерации.

Текущий стиль Render дважды рисует геометрию через ayagoz и overview. У overview maxzoom=13, и он продолжает использовать тайлы z13 при приближении (overzoom). Это может показывать грубую геометрию под подробной. Подготовленный стиль использует один источник. Этот дефект стиля не доказан как причина всех эпизодов нестабильности.

## Что изменено

- server.js: файл по умолчанию ayagoz-v3.mbtiles; абсолютный путь относительно папки приложения. Переопределение через MBTILES_FILE.
- Диапазон масштабов, слои и bounds читаются из карты; сервер проверяет SQLite и gzip перед запуском.
- XYZ-запросы преобразуются в TMS ровно один раз. Источник MapLibre использует scheme=xyz.
- Content-Encoding=gzip ставится только для реально сжатого тайла; несжатый PBF поддерживается.
- URL содержит хеш MBTiles, доступны ETag/304 и длительный кэш только для совпавшей версии. Старый URL версии отвечает 409 без кэша, чтобы не сохранить новую карту под старым ключом.
- Отсутствующий тайл отдаётся как пустой валидный MVT с X-Tile-Empty=1. Он не заменяется родительским тайлом, который имеет другую систему координат.
- /health показывает имя, размер, SHA-256 карты, коммит RENDER_GIT_COMMIT, версию сервера, масштабы, слои, сжатие, ошибки, пропуски и RSS процесса.
- /style.json и HTML не кэшируются. Стиль содержит границы данных и один источник.
- /search и /search-index.json работают при наличии необязательного addresses.json. Формат: массив объектов с label, lon, lat и необязательным kind (address/street/place). Отсутствие или повреждение файла не ломает карту. Индекс в этом пакете не создан: адреса не придуманы.
- Светлый стиль сохранён: категории дорог, контуры зданий, вода, зелёные зоны, железная дорога, подписи и цветные точки POI. Полноценные пиктограммы и окончательная визуальная настройка ещё не выполнены.
- Интерфейс ограничивает отдаление z11, чтобы не показывать уровень без дорог; сообщает о долгой загрузке, ошибках и выходе за границы карты. Поиск без базы отключается. Выбор точек и геолокация работают на уровне имеющегося интерфейса и не создают модули заказов такси.

## Проверки

В test-results.txt сохранён итоговый вывод двух успешно пройденных интеграционных тестов:

1. Все 1154 тайла через локальный HTTP-сервер совпадают с исходными сжатыми байтами; проверены gzip, XYZ→TMS, диапазон координат, /health, /style.json, кэш и 304, HEAD, OPTIONS, неверная версия и отсутствие тайла.
2. Несжатый PBF выдаётся без gzip-заголовка; повреждённый необязательный addresses.json не мешает запуску.

Стиль проверен валидатором @maplibre/maplibre-gl-style-spec 23.3.0: ошибок нет. Inline JavaScript и server.js прошли синтаксическую проверку. Это не заменяет проверку WebGL, подписей, мобильного экрана и консоли настоящего браузера.

## Как применить без поиска отдельных строк

1. Распакуйте ayagoz-map-fix.zip в отдельную папку. Файлы server.js и package.json содержат полный код; также обязательны index.html, style.json и ayagoz-v3.mbtiles рядом с ними. Старые версии сохранены как server.before.js и package.before.json для сравнения, а не как рабочая конфигурация.
2. Для локальной проверки откройте CMD в распакованной папке и выполните:

```cmd
npm install
npm test
npm start
```

Откройте http://localhost:3000 и http://localhost:3000/health. Если npm не установлен, официальный установщик Node.js доступен на https://nodejs.org/en/download. Дополнительная установка не нужна, если ваши node и npm уже работают. Для остановки нажмите Ctrl+C.

3. В GitHub откройте https://github.com/askhatr55-ui/ayagoz-taxi-map, ветку main, Add file → Upload files. Загрузите server.js, package.json, index.html, style.json. ayagoz-v3.mbtiles уже совпадает с приложенным файлом, повторно загружать его не нужно. Для воспроизводимых тестов добавьте также test/server.test.js с сохранением папки test через локальный git либо создайте этот файл в GitHub по пути test/server.test.js. Все файлы для запуска должны быть в одном коммите до деплоя.
4. В существующем сервисе Render проверьте Settings: подключён именно askhatr55-ui/ayagoz-taxi-map, Branch=main, Root Directory пустой (файлы в корне), Build Command=`npm install`, Start Command=`npm start`, Health Check Path=`/health`. В Environment удалите устаревшее значение MBTILES_FILE или поставьте `ayagoz-v3.mbtiles`. Убедитесь, что Auto-Deploy включён, если хотите автоматические обновления.
5. После коммита выберите Manual Deploy → Deploy latest commit и дождитесь успешного статуса. Сравните SHA коммита в Render Events с новым SHA в GitHub. Если build/deploy failed, откройте журнал: не делайте вывод по тому, что старая страница всё ещё работает.
6. Новый /health должен показывать serverVersion=`ayagoz-map-3.1.1`, mapFile=`ayagoz-v3.mbtiles`, tiles=1154, maxzoom=16 и полный mapSha256, указанный выше. Поле commit должно совпасть с новым GitHub SHA. Значение null означает, что идентификатор не предоставлен окружением; тогда установите GIT_COMMIT в Render равным SHA деплоя или сверьте SHA по Events. Хеш карты не подтверждает версию кода — проверяйте оба значения.
7. Откройте карту, проверьте центр, запад, север и юг на z13–16; приблизьте до z17–19 и проверьте overzoom. В DevTools → Network не должно быть 500/409 для текущих URL; в Console не должно быть ошибок MapLibre. Повторите на мобильном экране. Восточный участок без тайлов не станет заполненным после деплоя — это отдельная проверка данных.

Для отката используйте конкретный предыдущий успешный деплой в Render, предварительно записав его SHA. Не откатывайте на GitHub-коммит, где сервер требует отсутствующий ayagoz.mbtiles. Не удаляйте текущий сервис и не создавайте новый.

## Render Free и sql.js

Для карты примерно 2 МБ sql.js можно оставить: миграция SQLite не требуется для исправления найденных ошибок. Он загружает базу в память, поэтому при заметном увеличении MBTiles имеет смысл сравнить RSS с нативной библиотекой SQLite, например better-sqlite3, читающей файл с диска. У неё появляются требования к совместимости Node и сборке нативного модуля. Сейчас замена добавила бы риск без подтверждённой пользы.

Render Free засыпает после 15 минут отсутствия запросов; пробуждение занимает примерно минуту. Загруженные вручную на диск файлы исчезают при рестартах, поэтому MBTiles и индекс должны входить в GitHub-деплой. Постоянно работающий сервис такси на этом тарифе не гарантируется. Эти ограничения описаны в https://render.com/docs/free; холодный старт не доказан как причина всех текущих пустых участков.

Карта использует собственные OSM-тайлы. Библиотека MapLibre и шрифтовые glyphs пока загружаются с внешних CDN, как в действующей версии; полный автономный хостинг этих ресурсов ещё не реализован. Сохранена ссылка атрибуции OSM. При распространении MBTiles соблюдайте условия ODbL: https://www.openstreetmap.org/copyright и https://opendatacommons.org/licenses/odbl/1-0/.

Дальнейшие этапы — поиск по исходному PBF, пиктограммы и уточнение отсутствующих данных — следует продолжать после успешного деплоя и визуальной проверки. Маршрутизация, сервер заказов и Flutter не разрабатывались.
