# Поиск для карты Аягоза и будущего Android-приложения

Это обновление картографической части, без маршрутизации и заказов такси. Исходный PBF прочитан локально; на Render файл Казахстана, Python и библиотеки извлечения загружать не нужно.

## Что загрузить

Распакуйте `ayagoz-search-3.2.0.zip`. В существующем репозитории https://github.com/askhatr55-ui/ayagoz-taxi-map загрузите в корень **четыре файла**:

1. `addresses.json` — настоящие адресные объекты, именованные улицы и места из OSM.
2. `server.js` — полный сервер 3.2.0 с поиском по русским и казахским названиям.
3. `index.html` — полный веб-интерфейс с поиском и выбором точки по результату.
4. `package.json` — настройки версии, зависимость sql.js осталась прежней.

Нажмите Commit changes. Затем в существующем Render-сервисе выберите **Manual Deploy → Deploy latest commit** и дождитесь успешного деплоя. Файлы `style.json` и `ayagoz-v3.mbtiles` остаются от уже исправленной версии с Noto Sans Regular; повторно загружать их не требуется. Архив обновления не является отдельным проектом и предназначен для добавления в существующий репозиторий.

## Проверка после деплоя

Откройте https://ayagoz-taxi-map.onrender.com/health. Должны появиться:

- `serverVersion`: `ayagoz-map-3.2.0`.
- `searchIndex`: `true`.
- `searchEntries`: число из search-report.json, приложенного к архиву.
- `mapSha256`: `4d3ffc8cdceecc4fea2b4848abeb561c63a5f0ee3deaeead7c57eecf80e1a011` — карта не менялась.
- `commit`: тот же коммит, что указан в успешном деплое Render и GitHub.

Обновите страницу карты через Ctrl+F5. В поиске вводите часть названия улицы или организации. Для дома вводите улицу и номер; если в OSM у дома нет улицы, он ищется только по имеющемуся номеру. Примеры реальных названий и адресов указаны в search-examples.json.

Если сначала нажать «Откуда» или «Куда», а затем выбрать результат поиска, точка будет установлена на карте. Координата для здания вычислена внутри его геометрии, для улицы — на её сегменте. Это не подтверждённый подъезд или въезд: пассажиру следует уточнить точку посадки на карте. Не переходите к разработке маршрутизации, пока эта проверка не пройдена.

## API для Android

Будущее Flutter-приложение сможет использовать тот же запрос:

```text
GET https://ayagoz-taxi-map.onrender.com/search?q=название
```

Параметр q нужно URL-кодировать стандартными средствами клиента, например Uri в Dart. Ответ содержит `available` и массив `results` (до 12 результатов). У каждого результата есть `label`, `kind` (`address`, `street`, `place`), `lon`, `lat`, `osmType`, `osmId`, `coordinateType`, `aliases`, `street`, `housenumber`, `city`, `category` и `searchText`.

Названия берутся из `name:ru`, `name`, `name:kk`; поиск учитывает все сохранённые варианты. Регистр и ё/е нормализуются. Сегменты улицы с одинаковым названием объединяются в выдаче. Исправление опечаток и полноценный геокодер пока не реализованы. Веб-интерфейс загружает небольшой индекс через /search-index.json; Android может пользоваться /search, не скачивая весь индекс.

## Источник и ограничения

Источник — `kazakhstan-261008.osm.pbf`. Обработаны узлы, линии, замкнутые здания и собранные мультиполигоны отношений; внутренние дворы учтены при выборе точки. Проверены границы 80.30/47.90–80.55/48.05. Сведения о количестве объектов, SHA-256 исходного файла и пропусках — в search-report.json. Сегменты и отдельные OSM-объекты в индексе не означают число уникальных улиц или физических домов.

Не добавлялись отсутствующие улицы, номера домов или организации. Теги associatedStreet не использованы для дополнения неполных адресов. Наличие организации в OSM не подтверждает её актуальный режим работы. Координата объекта не гарантирует доступную автомобильную точку посадки.

## Повторное извлечение на вашем компьютере

Это не требуется для установки: готовый addresses.json уже создан. Скрипт extract_addresses.py приложен целиком для следующего обновления OSM. В CMD в папке со скриптом:

```cmd
py -m pip install osmium==4.3.1 shapely==2.2.0
py extract_addresses.py "C:\Users\albek\Downloads\kazakhstan-261008.osm.pbf" --output addresses.json
```

Обработка исходного файла требует существенно больше памяти и времени, чем работа сервера с готовым индексом. Выполняйте её локально. API обработки геометрий: https://docs.osmcode.org/pyosmium/latest/user_manual/03-Working-with-Geometries/.

## Проверки пакета

В search-test-results.txt сохранены результаты проверок API поиска по реальным объектам и выдачи всех 1154 тайлов. Синтетический тест extractor_test.py отдельно проверяет адрес без улицы, двуязычное название, линию и отношение-мультиполигон с внутренним двором; его тестовые адреса не включены в реальный addresses.json.

Изменения не опубликованы автоматически. После загрузки файлов ещё требуется проверить реальные результаты на сайте и в мобильном браузере.
